# 容量不足时完整退出浏览器：补测报告

结论：**本次实测通过，未发现需要修改生产代码的问题。** 浏览器完全退出后，使用原临时配置恢复上次会话，仍可打开设置、清理空间并恢复记录；人工分类及书签保留，已删除记录未被旧 AI 结果恢复。

## 测试过程与结果

1. 创建模拟当前标签人工分类、历史待分类记录、实际测试书签及独立书签分类元数据，发起一个由本机服务暂缓返回的历史 AI 请求。
2. 将测试存储填充到插件容量保护阈值以上、Chrome 硬配额以下，确认界面数据进入容量不足回退。
3. 使用 Chrome 的 `Browser.close` 完整退出浏览器，等待主进程退出码为 0；随后以同一配置目录启动新进程，核对进程 ID 已改变，恢复上次标签会话。
4. 重启后仍显示容量不足提示，当前标签人工分类和待处理历史记录保留；测试书签、目录结构及书签分类元数据与退出前一致。
5. 打开真实设置界面，通过“清理预览缓存”按钮释放空间，确认容量提示消失；再调用清空回顾记录入口对应的后台操作。
6. 创建新模拟标签，确认标签事件将新记录保存，记录开关仍开启，原人工分类及书签数据保留。
7. 尝试释放退出前的 AI 响应，并显式重放携带旧分类版本的提交；旧连接不会跨浏览器进程续用，重放提交被拒绝，已删除记录保持删除。
8. 清理完成后再次完整退出、重新启动。再次确认清理结果已持久化、人工分类及书签未丢失，重放旧 AI 提交仍被拒绝。

通过的测试运行使用三个不同的 Chrome 主进程，均核对正常退出；不是仅关闭标签、刷新页面或重启扩展后台。

- 新增可重复脚本：`scripts/quota-browser-restart-check.mjs`。
- Chrome 151 独立临时配置，两次完整退出与重新启动验证通过。
- 原自动化测试 **124/124 通过**；静态检查通过。
- 实际书签和文件夹属性完整比较；排除 Chrome 每次启动重新生成的虚拟根节点时间，不忽略用户书签的内容或分类变化。
- 本轮覆盖正常退出并恢复上次会话，不代表断电、磁盘损坏或强杀整个操作系统的测试。
- 生产代码未修改，只新增测试脚本与报告。

所有标签、书签、凭据和 AI 响应均为模拟。AI 地址仅解析到本机测试服务；不使用个人浏览器配置、不访问真实书签或邮箱。临时配置在测试结束后删除。
