# 慢响应与后台终止补测（2026-10-13）

结论：最终完整回归通过，未发现这些场景破坏历史补分类或普通整理的数据与恢复流程。新增测试及报告，未修改产品代码。

## 测试方式

使用 Chrome for Testing 151.0.7922.34、隔离的临时用户目录和真实 Manifest V3 扩展后台。加载的临时扩展副本逐文件与项目原文件核对，内容相同。没有修改产品代码。

供应商域名通过浏览器 DNS 映射到本机 HTTPS 服务，使用虚构页面和假 Key；不访问真实供应商、不发送用户浏览数据。服务端真实等待 45 秒后返回，未使用快进计时器。测试通过 CDP 检查后台 target 未连接调试器，避免调试连接维持后台存活而掩盖生命周期问题。强制终止使用 `ServiceWorker.stopWorker`，不是模拟发送一条错误消息。

工作流测试在扩展页直接运行原有工作流模块，禁用该宿主页的 dashboard 自动启动以隔离操作；界面测试另开未禁用脚本的真实 dashboard，从用户按钮进入和重试。

上述分类场景同时核对已有分类和人工保留“待整理”的记录未被覆盖。

## 回归脚本

新增 `scripts/lifecycle-check.mjs`。使用 Node.js 22 或更高版本、OpenSSL，以及支持加载未打包扩展的 Chromium：

```sh
CHROMIUM_EXECUTABLE='/绝对路径/Chromium可执行文件' node scripts/lifecycle-check.mjs
```

完整运行约需 3–4 分钟，包含真实 45 秒等待和 90 秒超时。设置 `LIFECYCLE_UI_ONLY=1` 可单独运行真实界面中断与重试测试。脚本结束时关闭测试浏览器、HTTPS 服务并清理临时目录。

本轮 `npm test` 88/88 通过，`npm run check`、脚本语法检查和 `git diff --check` 通过。

## 范围限制

这次验证的是请求慢响应、指定 MV3 worker 被终止、重新唤醒及重试；不等同于整台机器断电、整个浏览器进程崩溃、磁盘损坏或真实供应商的所有网络故障。后台终止会使正在进行的请求失败；系统保留已完成结果，由用户重试剩余页面，不承诺请求无感续传。
