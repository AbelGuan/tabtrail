## [P2] 同一面板忘记 Key 后，后续保存被误判为并发冲突

位置：`extension/dashboard.js:355`，关联 `extension/background.js:136`、`extension/dashboard.js:262` 和 `extension/dashboard.js:354`。

复现：

1. 打开设置，当前供应商已有保存的 Key。
2. 点击“忘记 Key”，等待成功。
3. 保持设置页打开，输入替换 Key，点击保存。
4. 页面提示“设置已在其他窗口更新，请关闭并重新打开设置后再保存。”；设置页仍打开，替换 Key 没有保存。

无需其他面板并发写入，也不需要容量不足即可触发。后台忘记操作正确地增加 `settingsRevision`，但前端 `settingsBase` 仅在打开设置页时记录；忘记操作后的 `load()` 刷新了 `state`，没有同步处理当前编辑会话的基准。随后的保存使用旧签名，必然被后台拒绝。保存其他设置同样会受影响。

影响：用户执行正常的“忘记旧 Key → 输入新 Key → 保存”流程失败，必须关闭并重新打开设置，并重新填写修改。删除本身成功，未观察到 Key 泄露、串用或数据丢失。

修复建议：让忘记操作与当前设置编辑会话的并发基准一致，并返回可验证的提交版本；成功后合理更新或重建该编辑会话。不能只在任意 `load()` 后无条件接受最新版本，否则可能把另一个面板的修改覆盖掉。应补测同面板忘记后保存成功，以及其间另一面板修改时仍正确拒绝过期表单。
