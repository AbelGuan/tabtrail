# 网页预览与列表/网格导航修复

日期：2026-10-14，版本：0.1.2。

## 原问题及修改

1. 预览只有占位、手动保存报错：原实现仅能显式截取当前可见网页；完整插件标签本身占据前台时，目标网页处于后台，保存必然被拒绝。现在在设置提供独立的自动预览授权，授权后只截取实际浏览的当前可见网页；弹窗有可用的打开/授权入口，只有目标网页当前可见时才提供手动保存。
2. 列表左侧和递减竖条不能打开：原来这两块只是装饰 `div`。现在是带打开动作的按钮，普通内容空白也可打开；预览和分类按钮独立处理，避免事件冒泡重复打开。方向键仍每行一个停留位置。
3. 网格点击只打开预览而无法跳转：卡片主按钮现在打开网页，预览和分类为独立工具按钮。网格会批量读取当前展示条目的本地缓存，使用懒加载图片，不为缩略图打开网址。
4. 异步图片及清理：显式预览不再被行鼠标移出取消；旧请求不会覆盖新预览；缓存清理或排除后，网格和预览弹窗移除旧图片，而不是继续显示已删除缓存。

## 采集与资源约束

自动预览默认关闭，需用户主动开启并接受 Chrome 的可选 `<all_urls>` 权限。权限申请从点击动作直接发起；拒绝时不保存开启状态。

后台只处理聚焦窗口里普通、已加载的活动 HTTP/HTTPS 标签；暂停记录、无痕、原排除域名及常见邮箱跳过。激活/加载事件延迟约 1.1 秒，图片已保存 5 分钟内不重复自动采集。切换标签、导航或撤销权限会使在途截图失效，包括切走又切回的场景。不会打开隐藏书签、切换后台标签或请求第三方网页截图。

截图在本机缩小至最多 640×400；最多 100 张，总数据约 1.5 MB，保留 7 天。图像缓存与记录、书签分类独立；写入仍经过统一容量保护，失败不删除人工分类或书签。截图不加入 AI 请求。常见邮箱列表不涵盖所有自建服务，其他敏感站点可通过排除域名保护。
