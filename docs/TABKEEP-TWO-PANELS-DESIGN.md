# 拾页 / Tabkeep 双面板设计讨论稿

状态：供讨论，不代表已批准开发。本文只梳理产品设计，没有修改插件代码、权限或配置，也没有读取个人书签、邮箱及登录状态。

建议方向：**标签页管理当前工作，书签页管理长期收藏；共用浏览与整理体验，各自保留数据来源和操作含义。**

## 1. 整体结构

新增顶层切换“标签页｜书签”，现有三个入口仍放在标签页内，名称和功能保持。

```text
拾页                 [ 标签页 | 书签 ]                搜索  更多
                         │
             ┌───────────┴─────────────┐
          标签页                       书签
   工作区 / 每日回顾 / 继续浏览      原文件夹 / 智能分类
             │                         │
     当前标签、时间与历史          浏览器收藏、分类视图
```

首次打开仍进入“标签页 → 工作区”。两个面板分别记住自己的筛选、滚动位置和已选分类；切换面板不会清空搜索或改变分类。启动是否恢复上次面板，可留作后续偏好选项，不作为首版必需功能。

主题、颜色和语言是全局设置：继续支持经典与圆角、跟随系统/浅色/深色、中英文。首次使用仍默认跟随系统、圆角、按系统选择语言。

全页模式和 Chrome 侧边栏模式使用同一套功能。侧边栏宽度有限，分类导航改为抽屉或下拉选择，主区域保持单列；不能把桌面左右两栏直接压窄。键盘与触屏用户也能打开预览和操作菜单。

## 2. 标签页面板：扩展入口，保留现有能力

默认保持现有工作区卡片布局、卡片大小调整和排序习惯。参考网站的紧凑列表可以成为以后可选的列表视图，不在加入书签时强制替换现有布局。

| 现有区域 | 保留的行为 | 双面板之后的关系 |
| --- | --- | --- |
| 工作区 | 当前标签同步、自动分类、规则优先、人工分组、搜索、详情、工作区管理 | 仍只管理标签工作区 |
| 每日回顾 | 时间分布、网站/工作区视角、小时与刻钟筛选、浏览路径与页面访问记录 | 不把收藏时间当作浏览时间，不伪造书签阅读记录 |
| 继续浏览 | 按日期查看记录、历史补分类、恢复标签、打开去重 | 仍使用历史快照，不被书签分类改写 |
| 分类与设置 | 多供应商配置、Key 管理、连接测试、偏好、规则优先级与导入导出 | 原配置继续有效，不自动扩大到书签 AI 整理 |
| 隐私与运行保护 | 暂停、排除网站、无痕不记录、保留期限、清空浏览记录、分批与失败重试 | 保持现有含义；书签与图片缓存有各自清理入口 |

尤其保留历史补分类的边界：只处理所选日期、当前范围内的待整理记录；保留已有分类和人工调整；先匹配规则，再按用户选择使用 AI；不打开网页；已完成批次和快照保留，中断后可续做剩余部分。

日常自动分类继续保护人工分组。现有“重新分组”则仍是用户预览范围并确认后的重新评估，可以包含人工分组；不能在新增功能时悄悄改变这一区别。

## 3. 书签面板：先尊重原目录，再提供整理视图

首次进入展示用途说明和“连接浏览器书签”入口。没有授权时仍可正常使用全部标签功能，开发时仅用虚构书签演示。

桌面布局建议如下：

```text
[标签页 | 书签]                    搜索书签        更多
[原文件夹 | 智能分类]
──────────────────────────────────────────────────
分类导航                    当前文件夹路径 / 分类名   数量
  全部书签                  图标  标题             操作
  书签栏                    域名 · 原文件夹路径
    开发资料                图标  标题             操作
    设计参考                域名 · 原文件夹路径
  其他书签                  ……
```

**原文件夹视图**是默认视图。读取浏览器已有的层级、名称和顺序；点击文件夹看该文件夹的直接子项，子文件夹可以继续进入，面包屑用于返回上层。“全部书签”则汇总可展示的书签，并显示原路径。同名文件夹按路径区分；同一网址被收藏在不同文件夹中，仍是不同书签，不擅自合并。

搜索默认覆盖当前视图的全部可展示书签，可明确切换到“当前文件夹”；结果显示路径。“智能分类”中的搜索同样支持“全部分类/当前分类”，界面始终标明范围。

**智能分类视图**是额外的虚拟分类，不等于移动浏览器文件夹。首次由用户点击“整理书签”进入预览，可选择文件夹或搜索结果、仅本地规则或 AI。完成后按主题展示；每条书签仍可查看原文件夹路径。

日常补分类只处理新增或待整理项，保护已经确认的分类和人工调整。新增书签可以自动出现在目录里，但不因已有标签 AI Key 就自动上传全部书签；书签 AI 整理单独启用。分类更新、原目录更新和图像更新各自独立。

首版建议一个书签只有一个主要智能分类，避免一开始引入多标签、集合和文件夹三套重叠概念。分类名称可以与工作区同名，但重命名一边不会自动改动另一边。

首版书签操作建议只提供：打开、查看原路径、搜索、虚拟分类、人工调整分类。原生书签重命名、移动、删除和批量写回放到后续单独设计；在此之前，用户可通过浏览器书签管理器编辑，拾页接收变化并更新展示。

## 4. 哪些共用，哪些独立

| 能力 | 可以共用 | 必须区分 |
| --- | --- | --- |
| 页面结构 | 品牌、面板切换、搜索入口、更多菜单、空状态 | 面板内导航和统计口径 |
| 条目展示 | 图标、标题、域名、操作菜单、预览卡片 | 标签显示工作区；书签显示目录路径及分类 |
| 搜索 | 输入框、匹配与高亮体验 | 默认只搜索当前面板，不混入另一类结果 |
| 分类 | 规则匹配、批次进度、建议确认、人工优先的原则 | 标签工作区、书签分类、原生文件夹分别存储 |
| 分类规则 | 规则编辑与优先级交互、导入导出界面 | 原有规则默认仍只作用于标签；用户明确复制或选择作用范围后才用于书签 |
| AI | 供应商配置与请求机制 | 两个面板分别启用；请求范围和上下文不自动混合 |
| 预览 | 展示组件、缓存读取、更新时间、禁用网站设置 | 来源类型、权限、URL 匹配和图片是否过期 |
| 导航状态 | 一致的返回、筛选、键盘操作 | 各面板独立保留选中项和滚动位置 |
| 错误恢复 | 已完成结果保留、明确进度、可重试 | 只重试各自剩余项目，不能串写另一类数据 |
| 清理 | 同一个设置入口、可见的范围说明 | 浏览记录、虚拟分类、图片缓存和原生书签不能一起隐式删除 |

共用组件不表示所有动作都应该一样。例如，关闭标签和删除书签含义不同，不应复用一个容易误操作的“删除”按钮。

后续可以增加“把标签收藏到指定文件夹”和“此网址已收藏”的关联提示，但不作为此次基础设计的前提。书签打开后是否已有标签，可提供“切换到已打开页”与“另开一页”；只是识别关联，不合并两种记录。

## 5. 缩略图：统一展示，明确来源

### 默认体验

鼠标停留约 350 毫秒后显示预览卡，离开条目和卡片后关闭；快速扫过列表不连续弹窗。悬停延迟是设计初值，后续用体验测试调整。键盘通过明确的“预览”按钮打开，Esc 关闭，焦点返回原条目。触屏也使用该按钮，正常点击标题仍执行打开或切换。

桌面预览卡出现在条目附近，自动避开窗口边缘，不挤动列表。窄侧边栏用面板内详情层展示，同一时间只打开一个。卡片包含图片或占位、标题、域名、所属分类、图片更新时间，以及打开/切换入口。

### 图片来源与状态

| 情况 | 用户看到什么 | 是否访问目标网站 |
| --- | --- | --- |
| 有可用的本地预览 | 截图和“上次保存于……” | 悬停时不访问 |
| 从未保存预览 | 标题、域名、分类和“暂无预览” | 不后台打开网址 |
| 缓存已旧 | 旧截图及日期，提示“非实时画面” | 不自动刷新 |
| 用户在目标网页主动保存 | 更新该页本地截图 | 用户已经打开该页，不另开隐藏网页 |
| 网站被禁止预览 | 普通信息卡或“此网站不保存预览” | 不采集图片 |
| 浏览器不支持截图或授权失败 | 保持普通信息卡，提示原因 | 不妨碍原有打开与分类 |

Chrome 的 `captureVisibleTab` 截取指定窗口当前活动标签的可见区域，需要相应权限。`activeTab` 可由扩展按钮、命令快捷键等明确用户操作临时授予；不能假设在书签列表悬停就能获得任意网页截图。[截图 API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab)、[activeTab 权限](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

因此建议首版采用“用户主动保存当前页预览”：用户在目标网页通过扩展按钮或指定快捷键执行保存，图片压缩后存本地。点击时的页面 URL 与截图完成时的 URL 必须一致，导航变化就放弃保存，避免截错页面。

明确取舍：首版不会让几千条旧书签立即都有真实截图，但没有图片的条目仍能完整使用。不要为追求图片齐全而在登录环境中批量访问网站。公开网站截图服务、网站封面图采集及自动刷新均留作后续独立选项，不偷偷启用。

### 复用、容量与隐私

同一浏览器配置中，书签与标签可按精确 URL 查找同一张缓存图片；不能仅按域名复用，也不随意删除查询参数或片段，以免不同页面显示同一张图。不同 URL、不同浏览器配置或无痕内容不混用。即使 URL 相同，图片也只代表保存时的画面，不保证当前账号或页面内容一致。

图片单独存储，和已有浏览记录分开计量；使用缩略尺寸与压缩格式，设置容量上限，并优先淘汰最久未使用图片。可先讨论 50 MB 作为上限初值，开发前再按实测确定。缓存写入失败只影响预览，不能阻塞记录、分类或历史恢复；清空图片缓存不清空分类。

预览默认关闭，按用户选择启用。邮箱、金融网站和企业后台不自动截图；提供预览排除名单和逐站允许机制。敏感网站无法靠内置名单识别完整，因此真正的基础保护是“不自动抓取、用户主动保存”。用户可以删除单张图片或清空全部图片；禁用某站预览时同时清除该站缓存。

图片不上传给 AI、不上传到截图服务，也不通过 Chrome 同步传输。后续若讨论云端图片功能，应作为全新的数据发送能力说明，而不是沿用分类授权。

## 6. 权限与个人数据边界

开发、界面演示和测试使用隔离浏览器、虚构书签与受控网页。此次方案不要求访问你的个人 Chrome 配置、书签文件、Cookie、邮箱或登录状态。

用户将来主动启用书签面板时，插件才申请 `bookmarks` 权限并读取浏览器书签。该权限在平台上允许读写，不是技术上强制只读的权限；首版需要通过实现和测试保证不调用原生书签修改接口。拒绝授权或撤销授权时，标签功能继续工作，书签面板显示重新连接入口。[Chrome 书签 API](https://developer.chrome.com/docs/extensions/reference/api/bookmarks)

本地展示标题、网址和目录不需要打开目标网页。书签 AI 则只在用户明确启用并选定范围后发送所需标题、域名、分类规则及偏好，不发送完整网址、截图、正文或目录路径；已有标签 AI 授权不自动扩展到书签。即使只有标题，也可能含私人信息，发送范围应可见、可排除。

现有网站排除设置对标签的行为保持原样。新增书签功能也尊重这些排除项：跳过拾页的持久索引、分类请求及预览；不删除 Chrome 中的原书签。用户仍可在浏览器原生管理器查看它们。预览单独禁用一个网站，则只影响图片，不扩大为删除书签或标签记录。

“清空浏览记录”继续只执行现有浏览数据清理，并清理依赖这些记录且无其他引用的预览；不能隐式清空原生书签、书签分类或书签专属缓存。新增“重置书签智能分类”“清空所有预览图片”两个范围明确的操作。

## 7. 以后开发时的验收底线

| 测试场景 | 应有结果 |
| --- | --- |
| 用户从不启用书签或预览 | 现有标签、回顾、历史补分类行为不变 |
| 加入书签面板或切换视图 | 不移动、删除、重命名原生书签，不改变标签分组 |
| 同网址出现在两个文件夹 | 两条书签及各自原路径保留 |
| 人工分组后再次补分类 | 人工结果保留；显式重新分组另行预览范围 |
| 历史补分类遇到慢响应或后台终止 | 保留已完成批次和快照，重试只处理剩余项 |
| 鼠标悬停一百条没有图片的书签 | 不打开新标签，不向对应网站、邮箱或截图服务发请求 |
| 预览权限拒绝、缓存超限或图片损坏 | 回退普通信息卡，分类、搜索和打开仍可使用 |
| 撤销书签权限 | 停止读取与整理书签，清理相应面板缓存，不影响标签功能 |
| 修改/删除虚拟分类 | 原生书签和其他面板数据不变 |
| 使用经典/圆角、深浅色、中英文或窄侧边栏 | 入口可达、预览不越界、键盘和触屏可操作 |

当前建议先认可产品边界，再讨论具体视觉稿。最核心的三个选择是：双面板各自保留数据；书签默认沿用原文件夹；预览以主动保存的本地截图为主。本文没有把这些建议当作开发授权。
