## 已修复的问题

### P2：异步设置检查可能混用两个表单草稿

首次配置的保存流程会等待已保存 Key 的检查。等待期间切换供应商并填写新 Key，旧代码使用先前读取的供应商和之后读取的 Key，可能把新供应商的 Key 保存到旧供应商名下。

现在在任何异步确认或 Key 检查之前，一次性固定供应商、模型、Key、其他设置、编辑版本和后续整理意图。保存对应点击时的完整草稿，继续由后台检查多面板冲突。真实浏览器复现测试修复前失败，修复后通过。

位置：`extension/dashboard.js` 的设置表单提交处理。

### P2：Key 生命周期没有完全纳入 AI 结果版本检查

标签页及历史分类上下文原来没有包含设置版本。更换 Key 后，在途旧结果仍可能通过回写检查。书签 AI 虽检查 Key 值，但“忘记后恢复同一个 Key”会绕过仅比较值的检查。

现在标签页、历史补分类和书签 AI 的上下文都包含持久化的设置版本。修改、忘记或恢复 Key 会使旧请求失效，包括 Key 值最终相同的情况。新的请求仍可正常重试；已完成的分类保留。

位置：`extension/core.js`、`extension/bookmark-ai.js`。

### P2：前台忽略最终提交拒绝

标签页工作流在最后刷新之后仍可能遇到并发修改。后台会拒绝提交，但前台原来忽略返回值，可能继续展示该批旧 AI 结果建议的规则。

现在工作流统一使用分类上下文检查，并在后台拒绝提交时立即以“设置已变化”结束，不记录该批进度或展示其建议规则。新增测试模拟最后刷新与提交之间的冲突，修复前失败、修复后通过。

位置：`extension/organize-workflow.js`。

### P2：旧版清空接口仍有多次删除窗口

当前界面已使用新的清理入口，但后台保留的旧 `clear` 接口仍依次清空停留记录、删除预览缓存、清空页面记录并暂停记录。最后一次保存失败时，前两步可能已经生效。

现在旧入口也先准备完整清理结果，再一次提交记录、停留、缓存、游标和设置版本。保留当前打开标签的人工分类、书签及 Key；成功后继续保留该入口原有的暂停记录行为。保存失败时，原本地状态完整保留。会话中的媒体标记仅在成功提交后清理，不会把已完成提交误报为存储失败。

位置：`extension/background.js`。新增测试修复前失败，修复后验证失败状态不变、成功仅一次提交、人工分类和书签/Key 保留。

## 统一审查范围及保护机制

| 范围 | 本轮核对结果 |
| --- | --- |
| 设置整体提交 | 设置、各供应商 Key、记录、缓存及书签分类相关修改使用同一提交；失败不出现部分保存 |
| Key 删除与迁移 | 空白输入保留有效 Key；忘记写入空值删除标记；旧会话 Key 不覆盖该标记；不同供应商保持独立 |
| 多面板 | 忘记前校验编辑基准；成功后返回实际提交版本；随后其他面板修改仍会阻止旧表单保存 |
| 容量不足 | 所有持久化写入经过容量裁剪；保护当前打开标签的人工分类；无法容纳时拒绝整次写入；读取回退保留设置和清理入口 |
| 自动/手动清理 | 保留当前打开标签状态，清理记录时递增历史版本；不从旧存储重新补入主动删除的记录；书签数据独立保留 |
| 崩溃恢复 | 提交前保留旧完整状态，提交后重启保留新完整状态；后台或浏览器重启后可清理并恢复记录 |
| AI 请求与回写 | 请求前检查范围和上下文；网络等待释放后台队列；提交时检查记录、人工调整、历史版本、设置版本；冲突结束旧批次 |
| 书签与历史补分类 | 保存现有分类和人工调整；书签确认范围及版本独立校验；历史只补指定日期的待整理记录，不重新打开网页 |

核对了后台消息入口、设置页面、Key 读取/迁移、容量写入器、自动维护、活动游标、缩略图、书签分类管理，以及标签页/历史/书签 AI 的请求和提交路径。最后复审确认新增检查同时在前台工作流和后台提交处生效，避免只依赖某一处校验。
