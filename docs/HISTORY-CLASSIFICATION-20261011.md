# “继续浏览”历史补分类修复

已完成历史补分类，保留已有分类和人工调整；本次未进行原型设计改版。

## 使用方法

1. 在 Chrome 扩展管理页重新加载原安装的扩展，再打开面板。不要卸载重装，以免删除本地记录。
2. 进入“继续浏览”，选择日期；需要时用搜索缩小范围。
3. 点击“补分类（数量）”，检查待处理页面后确认。
4. 本地规则先运行；勾选 AI 时按每批最多 200 页处理剩余页面，可能产生供应商费用。没有 Key 时仍可使用本地规则。

## 行为与保护

- 包括已经关闭的历史页面，无需重新打开标签。
- 只处理所选日期和搜索范围内的待整理记录；已有分组、已有快照分组及人工指定归属均保留，包括人工保留在待整理中的页面。
- 结果保存到当天分组快照，之后批量恢复会沿用该分组。浏览计时与其他日期不因补分类而改变。
- 已完成批次立即保存。失败后再次点击补分类，只处理剩余部分；AI 无法确定的页面仍保留待整理。
- 暂停记录、离开所选日期或面板不可见会停止后续处理。分类设置变化以及请求期间的人工调整会阻止过期结果覆盖数据。已发出的网络请求无法撤回。
- 仅能处理仍保留在扩展中的记录，无法恢复已过期、已删除或从未记录的页面。

## 验证

- `npm test`：84 项测试全部通过，涵盖 451 页分批、失败重试、已有分类保护、并发人工调整、暂停和设置变化、历史快照恢复等。
- `npm run check` 和 `git diff --check`：通过。
- `scripts/history-check.mjs`：Google Chrome 中运行真实工作流和后台处理代码，模拟 Chrome API 并拦截供应商请求；验证确认／取消、AI／仅规则／无 Key、已关闭页面、原分类保护、无新标签、中英文及经典／圆角窄屏界面。
- 浏览器验证未调用真实供应商，也未操作个人浏览记录；真实供应商响应质量和网络情况仍取决于用户配置。

主要实现位于 `extension/history-workflow.js`、`extension/background.js`、`extension/core.js` 和 dashboard 入口；使用与隐私说明已同步更新。
