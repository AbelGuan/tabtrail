# AI 配置与供应商适配

本文描述当前代码的适配方式，不是供应商最新模型目录。配置入口为“更多 → AI 配置与隐私”。使用自己的 API Key，调用费用由所选供应商收取。

## 配置步骤

1. 选择供应商，填写对应的 Key。不同供应商的 Key 不能混用。
2. 检查模型名称，改成你的账户实际支持的模型标识。
3. 可先点击“测试连接”，通过后保存。测试只检查固定 JSON 响应，不代表真实标签分类质量已经验证。
4. 保存后返回可见工作区，记录开启时会自动整理；已有分类需重做时使用“重新分组”。

每个供应商的 Key 分开保存，输入框留空表示保留已存 Key；删除须使用清除按钮。切换供应商会清空尚未保存的 Key 输入，不会删除其他供应商已存 Key。Key 和已保存的模型设置在重启后保留。

## 本地规则、AI 与费用

本地规则按标题和域名做关键词匹配，不调用 API。AI 分类最多每批 200 页，可能附带其他候选页面及已有工作区的参考信息；一次分类的输入不只包含当前这一页。

未变化的已分类页面通常复用结果。有新信息时会重新检查部分待整理页面；用户主动重新分组也可能产生请求。面板关闭或工作区不可见时不启动新的自动请求，后台本地记录可继续。

连接测试发送固定文字，不发送标签或规则。测试也会调用模型，可能产生费用。隐私、保存位置及删除方式见 [隐私说明](../PRIVACY.md)。

## 常见失败

| 提示 | 建议检查 |
| --- | --- |
| Key 无效／没有权限 | Key 是否属于当前供应商、是否有效、账户及地区是否支持该端点 |
| 模型不存在／参数不支持 | 模型标识是否正确，是否接受当前适配器的 JSON 格式和 token 参数 |
| 限流／额度不足 | 供应商余额、额度和速率限制；避免连续反复重试 |
| 连接失败／超时 | 网络、浏览器扩展的站点访问设置，以及供应商服务情况 |
| JSON 无效／输出被截断 | 模型响应未满足分类协议；可缩小主动重新分组范围，或改用兼容模型 |

自动分类失败后，五分钟内不自动重试，可通过“更多 → 同步标签”主动重试。测试连接成功不会自动保存设置，也不保证后续请求不再失败。

## 给维护者的协议说明

测试与分类共用 [ai.js](../extension/ai.js) 中的请求适配器：

- Anthropic 使用 Messages 结构和 `x-api-key`，包含浏览器直连标记。
- 其余使用 Chat Completions 结构和 JSON 对象输出格式；OpenAI 使用 `max_completion_tokens`，其他适配器使用 `max_tokens`。
- 百炼关闭思考；Kimi 仅对代码识别的 `kimi-k2.5`／`kimi-k2.6` 名称前缀发送关闭思考参数。
- 连接测试输出上限 1,024 tokens、30 秒超时；分类输出上限 8,192 tokens、每批 90 秒超时。
- 返回数据校验记录 ID、完整数量和分组名称。网络跳转被拒绝，以保持凭据发送端点固定。

改变适配器时同步检查 manifest 中的域名权限及 CSP，并运行供应商模拟测试。模拟通过只证明请求构造和响应处理，不证明真实模型存在、账户可用或分类准确。
