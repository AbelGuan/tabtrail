# 多面板、供应商切换与忘记 Key：组合补测

结果：**本轮补测通过，未发现需要修改生产代码的问题。** 多面板切换供应商、替换或忘记 Key，没有导致供应商之间串用，也没有恢复已成功删除的 Key。

## 新增覆盖

- 自动化测试排列两种供应商切换/替换和一次忘记操作的全部六种执行顺序，分别叠加正常存储与配额拒绝，共 12 组。旧版本面板不能覆盖后续状态；各供应商 Key 保持独立。
- 容量拒绝时，“忘记”操作失败并保留原 Key，不伪装为删除成功。释放压力后重试可成功删除；空白保存及旧会话值不会恢复它。
- 真实临时 Chrome 同时打开三个扩展面板，分别切换到 OpenAI、切换到 Gemini 并修改 Key、忘记 OpenAI Key；最终已忘记 Key 保持为空，其他供应商不受影响。
- 在容量不足下尝试忘记 Gemini Key，确认请求失败而整张 Key 表不变。
- 保留设置整体提交前后强制退出、重启及继续记录验证，并额外在“忘记 Gemini Key”的提交前、提交后分别强制退出整个测试浏览器进程组。
- 忘记提交前被中断：旧 Key 完整保留，可以重试；提交成功后被中断：重启仍为空。旧面板重放被拒绝，重新注入的旧会话值和空白表单保存均未恢复已删除 Key。
- 当前人工分类、实际测试书签及其分类保持预期；原已删除历史仍不存在，旧 AI 提交被拒绝。成功设置保存的书签修订号正常递增，不将版本变化误判为分类内容丢失。

## 验证结果

- `npm test`：**134/134 通过**，包含原有人工调整、书签 AI、历史补分类及清理交错回归。
- `npm run check`：通过。
- 新增 `scripts/provider-key-lifecycle-check.mjs`，真实临时 Chrome 完整通过，包含六次强制退出及重启。
- 新增组合测试位于 `tests/settings-atomic.test.js`。生产代码未修改。

测试中的“已删除”指提交成功的删除；容量拒绝或提交前中断时保留旧 Key 是正确结果。强制退出覆盖应用提交前与提交返回后，不代表硬件断电或磁盘损坏保证。

全部使用虚构 Key、模拟标签和书签、独立临时浏览器配置及本机 AI 模拟服务。未访问真实书签、邮箱、个人 Chrome 资料或真实供应商账户；只终止测试自行创建的浏览器进程组。
