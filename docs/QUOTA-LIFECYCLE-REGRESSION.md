# 容量不足、后台重启与多面板补测

结果：**全部通过，未发现需要修改生产代码的问题。** 本轮新增可重复运行的真实 Chrome 扩展生命周期测试，未访问真实书签和邮箱。

## 实测场景

使用独立临时 Chrome 配置，同时打开两个完整面板及一个侧边栏布局面板。测试存储逼近 Chrome 配额，并超过插件内部容量保护阈值；缓存可供清理，当前人工分类与历史待分类记录均使用模拟数据。AI 请求仅由本机模拟服务接收。

1. **容量不足、AI 请求等待期间强制终止后台**：通过 Chrome 的 ServiceWorker 停止命令终止实际扩展后台，等待停止事件；没有调试器附着在后台上维持其生命周期。
2. **三个面板同时唤醒后台**：原 AI 调用报告中断，重新读取返回容量不足提示；人工分类、历史记录及书签元数据与终止前一致，设置和清理仍可访问。
3. **多面板并发操作**：先清理缓存释放空间，再由两个面板同时发起清空回顾、清理旧记录，第三个面板同时读取数据；各请求成功，最终数据一致。
4. **清理后恢复记录**：新建模拟网页，等待真实标签事件将其保存；记录开关保持开启，人工分类及书签元数据保留。三个面板并发重新加载后均不再出现容量不足提示。
5. **重启前的旧 AI 结果**：终止后释放旧请求，并尝试提交旧分类版本的结果；提交被拒绝，已删除记录没有重新出现。
6. **后台保持运行的迟到 AI**：另起一次历史补分类请求，制造容量不足并完成并发清理后再返回模拟 AI 结果；历史流程返回 `changed`，应用数为 0，已删除记录保持删除。
