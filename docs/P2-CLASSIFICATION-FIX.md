# P2 分类请求时序问题已修复

工作区分类与历史补分类均已修复：等待 Key 时发生排除网站、暂停记录、清空记录、删除页面或人工调整，旧页面信息不会继续发送。

## 实现

- 两种流程共用发送前预检，重新读取状态并验证分类上下文及本批页面、待整理参考页面、已有分类参考页面。
- 最终校验和网络请求启动在后台串行队列中执行。若设置操作先完成，后续请求会被拒绝；避免“前端校验通过、后台设置刚好变化”留下第二个时间窗口。
- 供应商响应在队列外等待，暂停、排除、清空不被网络延迟阻塞。保留响应后的状态校验和人工调整保护。
- 请求仍有 90 秒超时，并仅在请求存续期间使用定时只读 API 调用维持后台任务，结束后清理。该方式参照 [Chrome 长操作生命周期说明](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers#keep-alive)。

已发出的请求无法撤回；其返回结果仍会经过现有提交保护。未改变本地规则、分批数量、失败重试、历史快照恢复和界面设计。

- 新增真实后台处理器测试：最终发送校验、记录变化、Key 清除，以及请求挂起时清空记录不受阻塞；任务维持计时器结束后清理。
