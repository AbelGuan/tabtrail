# 容量不足回退：复审结果

结论：**本轮未发现需要修复的新功能问题。** 清理释放足够空间后，标签记录能够恢复；失败写入未丢失人工分类；书签和保留范围内的历史补分类回归通过。

## 重点检查

| 场景 | 结果 |
| --- | --- |
| 容量不足时加载、进入设置及查看存储信息 | 读取已保存数据，清理入口可用 |
| 清理缓存、清理旧记录、清空回顾记录后 | 原记录开关保持开启；新标签写入成功，后续采样产生新的停留记录 |
| 浏览器拒绝写入 | 本地数据与写入前完全一致，当前标签人工分类保留 |
| 书签人工调整写入失败 | 明确失败，已有书签分类、规则和版本未被覆盖 |
| 清理成功，随后的采集写入失败 | 回退读取清理后的最新记录及版本，不恢复已删除内容 |
| 书签读取与标签清理 | 模拟书签仍可读取；书签人工分类及元数据保持不变 |
| 保留的历史待分类记录 | 清理后仍可应用规则补分类；已删除日期不会重新出现 |
| 清理期间 AI 返回 | 既有回归通过：标签及历史迟到结果不恢复删除记录，书签 AI 与标签历史清理保持独立 |

## 验证证据

- `npm test`：**124/124 通过**，包含容量保护、历史补分类、书签 AI、慢响应、后台重启/重试相关回归。
- `npm run check`：通过。
- 加强 `tests/quota-availability.test.js`：启用模拟活动采样，验证三种清理方式后实际新增页面和停留记录，而不只判断空间提示消失；验证书签修改被拒绝时数据完整不变。
- 加强 `scripts/quota-ui-check.mjs`：独立临时 Chrome 扩展配置、20000 条模拟书签分类元数据、接近配额的存储。打开设置、浏览模拟书签、清理缓存后，通过浏览器标签事件确认新页面真正保存，原人工分类仍保留。
- 测试有效性检查：临时反转容量错误识别条件，5 项容量回归全部失败；恢复原条件后完整测试通过。生产代码未留下修改。

本轮只保留测试增强和本报告。测试覆盖的容量错误包括模拟浏览器配额拒绝，以及真实临时扩展中的内部容量保护；没有把测试通过解释为任意设备、任意存储故障均有保证。若清理未释放足够空间，新写入仍应失败并保留旧数据。

所有书签、标签、存储数据及 AI 响应均为模拟，浏览器使用独立临时配置；未访问真实书签、邮箱或个人 Chrome 资料。
