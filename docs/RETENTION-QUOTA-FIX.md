# 当前标签人工分类的容量保护：P2 修复完成

已修复审核发现的问题，保留自动清理、手动清理、书签和历史补分类功能。

## 改动

- 所有生产代码的本地存储写入汇入 `storage-budget.js`，包括活动采样、配置、标签/历史分类、书签分类和缩略图写入。
- 写入前识别当前打开标签最近的人工分类状态，先预留空间，再裁剪可丢弃历史。保护不依赖记录在数组中的位置，也不依赖每日维护是否已经执行。
- 普通记录保留复用同一套容量保护函数，避免进入持久化入口前先丢失人工分类。
- 受保护数据可借用历史预算；如果总体空间确实不足，本次写入失败而不落盘，不静默删除人工分类。
- 容量裁剪导致历史删除时递增清理版本；旧配置写入不能把版本降回去。读取与同步返回实际保存后的版本。
- 只处理本次准备保存的记录，不从旧存储补回缺失条目，因此不会把显式清理删除的历史恢复。

## 回归结果

静态检查通过，**118 项单元与集成测试全部通过**。

| 场景 | 结果 |
| --- | --- |
| 原 P2：约 7.29 MB 模拟数据、人工分类位于数组前部，活动采样触发容量裁剪 | 人工分类保留，书签元数据不变 |
| 启动后先采样，再执行逾期维护 | 80 天前已知的当前标签人工分类成功保留为当前状态 |
| 记录、停留片段、配置、书签、缩略图、Key 等写入类型 | 共用保护规则，人工分类保留 |
| 受保护数据超过默认分配预算 | 借用历史预算，未截断或删除 |
| 总体空间无法容纳受保护数据 | 拒绝写入，旧存储保持不变 |
| 标签 AI 等待期间，关闭对应标签并清空回顾 | 迟到结果不恢复删除的记录 |
| 历史 AI 等待期间执行旧记录清理、清空或自动维护 | 旧结果失效，删除记录不恢复 |
| 书签 AI 等待期间清空标签历史 | 书签 AI 正常保存，标签历史仍为空 |

浏览器回归通过：历史补分类的确认、取消、规则处理、人工保护；书签分页、网格、跨页人工调整、完整搜索和缓存上限；真实 MV3 隔离环境中的历史人工快照、书签持久化且原目录不变、预览保护、关闭标签和侧边栏。

真实扩展测试还修正了原脚本在异步保存完成前立即读取结果的时序问题，改为等待保存完成后断言。

性能复测覆盖 100、1000、10000 条模拟历史，一万条清理计算约 12.5 毫秒。该时间不包含所有浏览器内存与磁盘行为，不代表 Chrome 总内存占用。
