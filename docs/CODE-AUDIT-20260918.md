## 已确认问题

### 1. [P2] 工作区迁移遗漏历史快照，恢复时会重新引入已删除工作区

- 位置：`extension/core.js:135`；关联 `extension/background.js:6,80`、`extension/dashboard.js:90`。
- 重命名和删除只更新 `record.group`，不更新 `snapshotGroup`。后台仅为今日记录或缺少快照的记录更新快照，已存在的历史快照继续使用旧名称。
- 复现：构造昨日属于“已删除项目”的记录，删除该工作区并迁移到“待整理”，再调用实际后台的 `restoreDay`。恢复后的今日记录重新归入“已删除项目”。历史列表也继续显示旧名称。
- 影响：与“同步更新历史记录”的界面承诺不一致；用户删除或重命名的工作区可能再次出现。
- 建议：管理工作区时分别迁移 `group` 和 `snapshotGroup`；历史快照可能与当前 `group` 不同，应独立匹配。保持阅读状态不变。补充带历史快照的重命名、删除、恢复测试。

### 2. [P2] 每日回顾中打开工作区管理会报错

- 位置：`extension/dashboard.js:191`。
- `renderWorkspaces()` 中混入了标签行的“切换次数”渲染代码，引用未定义的 `item`。
- 实际 Chrome 网页预览复现：进入每日回顾 → 更多 → 工作区管理；提示 `item is not defined`，管理弹窗不打开。有至少一个工作区时触发。
- 建议：删除这段误复制的标签元信息代码；补充从不同一级视图打开管理弹窗的交互测试。

### 3. [P2] 单独变化的页面标题不触发采集和增量分类

- 位置：`extension/background.js:46`、`extension/dashboard.js:403`；计时模块同类过滤在 `extension/activity-worker.js:51`。
- `tabs.onUpdated` 只处理 URL 或加载完成，忽略仅含 `title` 的更新。页面在加载后改变标题、且没有 URL／加载状态变化时，后台和面板都没有更新入口。
- 使用实际后台模块及模拟 Chrome 事件复现：先采集标签，再修改模拟标签的标题，仅分发 `{title: ...}`，存储记录仍为原来的标题。
- 影响：面板持续可见时，新标题不会及时用于搜索、展示或分类；其他同步事件发生后才会读取新标题。这与 README 的标题变化增量分类行为不一致。
- 建议：后台和面板同时处理标题变化，沿用现有去抖；补充只变化标题的事件测试。

### 4. [P2] 其他面板的分类和阅读状态修改不会及时同步

- 位置：`extension/dashboard.js:402`。
- 存储监听仅处理 `apiKeys` 和 `config`，忽略 `records`；人工修改、AI 分组和阅读状态保存恰好主要修改 `records`。
- 实际 dashboard 配合模拟 Chrome 存储事件复现：完成初始整理后，修改共享状态的分组并发送 `records` 变更事件，等待 2.2 秒，面板仍显示旧分类；手动“同步标签”后才显示新分类。
- 影响：同时打开侧边栏和完整面板时，可见面板会保留过期分类或阅读状态，直到另一个刷新入口被触发。争抢 AI 锁失败的面板也无法依靠分类结果写入事件更新。
- 建议：监听相关记录变化，并区分仅更新时间戳与真正展示数据变化；不能直接对每次 `records` 写入无条件调用 `get`，因为 `get → sync → 写 records` 可能形成刷新循环。补充多面板同步测试。

### 5. [P2] 扩展冒烟测试仍依赖已删除的历史入口

- 位置：`scripts/extension-check.mjs:37`。
- 脚本点击 `#history`，但当前 HTML 没有该 ID；入口已改为 `#continue-browsing`。即使扩展成功侧载，执行到此也会等待不存在的元素直至超时。
- 同时，新“继续浏览”默认选择昨天，而脚本记录是在当天生成，仅改选择器仍不能保留原断言。
- 建议：改用当前导航并显式选择测试记录的日期。静态 UI 引用检查目前只扫描 `dashboard.js`，应将浏览器回归脚本引用纳入检查。
- 本项由静态路径和 HTML 核对确认，未宣称实际跑通扩展侧载测试。
