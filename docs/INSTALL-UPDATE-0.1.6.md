# 拾签 / Pickmark 0.1.6 安装与更新

本包为清理后源码生成的本地体验版，尚未通过 Chrome Web Store 发布。版本号：**0.1.6**。

## 已安装用户：覆盖原目录更新

1. 完成正在保存的操作，关闭拾签页面及侧边栏。
2. 打开 `chrome://extensions`，找到原来的拾签，记下插件 ID 和原加载目录。**不要卸载原插件，不要另加载第二份。**
3. 如果原加载目录就是 `/Users/abelguan/Desktop/Tab/extension`，该目录已包含新版源码，直接点击原插件的「重新加载」。
4. 如果原加载目录在其他位置，将本包解压到一个临时目录，再把包内文件和子文件夹覆盖到**原加载目录**。保持原目录的位置和名称不变；`manifest.json` 必须直接位于原加载目录内，不能多套一层文件夹。
5. 在 `chrome://extensions` 点击原插件的「重新加载」，确认版本为 **0.1.6**，插件 ID 与更新前相同。
6. 打开拾签，确认原有分类、书签智能分类及规则仍在；进入「继续浏览」核对保留范围内的历史记录和补分类入口。

本次打包没有修改其他旧加载目录。目录如 `dist/Pickmark-0.1.2/`、`dist/Pickmark-0.1.3/` 仍是原内容；如需更新它们，由你按上述步骤覆盖原目录。

## 数据和权限

- 不新增升级专用的数据清空或重置，不变更存储键。更新需继续使用原 Chrome 配置和原插件 ID，才能读取原有本地数据。
- 当前标签的人工分类、分类规则、书签智能分类元数据、历史记录、供应商 Key 和缓存沿用原存储。原有保留期限、容量维护和排除网站设置继续生效；超出这些策略的历史不会因更新而获得永久保留。
- 书签原目录和浏览器导航页不由本次更新改写。书签 AI 仍需确认处理范围；自动网页预览仍需主动开启并授权。
- 本次未新增权限。不要通过卸载重装来更新，卸载可能清除扩展数据；换目录加载第二份也可能产生不同的插件 ID。

## 首次安装

将 ZIP 解压到一个计划长期保留的固定目录。在 `chrome://extensions` 开启开发者模式，选择「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的目录。首次安装不会自动拥有另一份插件的数据。

## 回退

项目保留的 `dist/Pickmark-0.1.4.zip`、`dist/Pickmark-0.1.5.zip` 及校验文件未被覆盖，更早的包位于 `archive/2026-10-26/releases/`。确需回退时，关闭拾签，将完整旧包覆盖到同一加载目录后重新加载；不要卸载。Chrome 允许回退及旧版本能否理解较新数据仍以实际情况为准，不承诺任意版本间回退。

## 文件校验与本次范围

同目录的 `Pickmark-0.1.6.sha256` 用于校验 ZIP 完整性。macOS 可运行：

```sh
shasum -a 256 -c Pickmark-0.1.6.sha256
```
