# 容量不足与清理期间强制退出：补测报告

结论：**本次强制退出测试通过，未发现需要修改生产代码的问题。** 重启后可以清理并恢复记录，人工分类和书签保留，已经提交的删除不会被旧 AI 结果恢复。

## 实测结果

使用 Chrome 151、同一份独立临时配置、模拟标签及书签。每次通过 `SIGKILL` 终止本次测试浏览器的独立进程组，核对进程以该信号退出，再启动新的浏览器进程恢复会话。

| 强制退出时机 | 重启后结果 |
| --- | --- |
| 存储已触发容量保护，仍未清理 | 人工分类、待分类历史、实际测试书签和书签分类元数据保留；设置与清理入口可用 |
| 清理已计算出新记录集合，即将提交存储 | 清理尚未提交，完整旧记录保留；可以重新清理，没有部分丢失人工分类或书签 |
| 清理提交返回后立即强制退出 | 删除结果保留，旧历史不再出现；新标签可继续保存，记录开关保持开启 |
| 恢复记录后再次强制退出 | 人工分类、书签及删除结果继续保留，旧 AI 提交仍被拒绝 |

清理提交前的中断使用调试断点准确定位到 `writeLocal` 调用 `chrome.storage.local.set` 之前，并核对待提交集合包含人工分类、已排除待删除历史，然后终止整个测试浏览器进程组。生产代码未改动。

AI 验证使用此前由本机模拟服务捕获的历史分类请求及旧版本提交：尝试释放旧响应，并在清理后和再次重启后重放旧提交，均未恢复已删除记录。浏览器被终止后原网络连接不会跨进程续用；显式重放用于额外验证版本保护。

## 验证与边界

- 新增脚本：`scripts/quota-crash-check.mjs`。
- 一轮包含四次真实强制退出及对应重启；人工分类、实际书签目录和独立书签分类均有断言。
- 先正常保存测试基线，再执行强制退出，避免把尚未落盘的测试书签创建操作混入已有数据保护测试。
- 原自动化回归 **124/124 通过**；静态检查通过。
- 未发现本轮需要修复的问题，仅新增测试与报告。
- 这里模拟的是进程骤停，不是硬件断电或文件系统损坏；断点覆盖应用提交前和提交返回后，没有宣称控制了 Chrome 内部数据库写盘的每个瞬间。未提交的清理保留旧记录属于预期行为，不等同于 AI 恢复已删除记录。

只使用临时浏览器配置。强制退出仅针对测试自行创建的进程组；所有标签、书签、凭据与 AI 数据均为模拟，AI 服务只运行在本机。未访问真实书签、邮箱或个人浏览器资料，测试结束后删除临时配置。
