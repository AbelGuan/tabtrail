# Tabtrail

**简体中文** | [English](README.en.md)

**把散落的标签页整理成主题工作区，回看浏览过程，接着上次的思路继续。**

Tabtrail 是一个桌面 Chrome 扩展。它把当前打开的页面呈现在独立的主题卡片中，支持本地关键词规则和可选 AI 分类；同时在本机记录每日页面清单与浏览时间估算，帮助你找回之前的内容。

当前版本：**0.1.0 · 实验性版本**。尚未上架 Chrome Web Store，可通过源码加载。AI 需要你自己的供应商 API Key；不配置 AI 也能使用本地规则、手动分类、回顾和继续浏览。

## 为什么做 Tabtrail

Tabtrail 起于开发者自己的一个日常困扰：每天打开很多标签页，原本正在关注一个问题，却又被新的内容吸引。到一天结束时，浏览器里留下了许多页面，但已经很难回想，自己的注意力究竟落在了哪些内容上，又是怎样从一个主题转向另一个主题的。

这个想法最初被称为 **Attention Atlas（注意力版图）**：希望为每天分散在不同内容上的注意力留下一些可回看的线索。它关心的不只是“如何收拾标签页”，也包括“今天我关注了什么，思路走到了哪里，以及接下来想回到哪一页”。

**Tabtrail 是插件的名字，Attention Atlas 则保留为它的创作动机与愿景。** 当前版本通过主题工作区、浏览时间估算和切换轨迹，帮助用户自己回顾。这些记录不能直接衡量人的注意力，也不会自动判断专注、分心或任务完成；愿景不代表插件已经具备这些判断能力。

## 可以做什么

| 功能 | 使用方式 |
| --- | --- |
| 工作区 | 汇总普通窗口中当前打开的网页，按主题查看，点击回到原标签；同一完整网址合并为一条页面记录 |
| 自动整理 | 工作区可见且记录开启时，先应用本地规则，再用已配置的 AI 处理需要分类的页面 |
| 每日回顾 | 按网站或工作区查看时间分布，按小时或 15 分钟查看切换轨迹，点击详情里的页面继续浏览 |
| 继续浏览 | 默认查看昨天，也可选择其他日期；重新打开清单中尚未打开的页面 |
| 规则与偏好 | 编辑、排序和备份关键词规则；填写 AI 分类偏好，选择仅在本次浏览器会话使用或长期保存 |
| 界面与控制 | 中文 / English；经典 / 圆角布局；浅色 / 深色 / 跟随系统；工作区管理、排序和卡片尺寸调整 |

整理发生在扩展面板内。浏览器原来的标签顺序和分组保持不变，扩展不会自动关闭标签，也不会接管新标签页。

每日清单表示“采集时打开过的页面”，**不等于已经阅读的页面**。停留时间与切换轨迹用于回顾，不判断你是否专注、分心或完成任务。当前没有 AI 每日总结、笔记、待办状态、云同步或账号系统。

## 安装：不需要写代码

使用近期版本的桌面 Chrome。普通使用者不需要安装 Node.js、Python 或运行命令。

1. 在本仓库页面点击 **Code → Download ZIP**，解压到一个准备长期保留的文件夹。
2. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择项目里的 **`extension` 文件夹**。该文件夹内应直接有 `manifest.json`。
4. 在 Chrome 工具栏的扩展菜单中固定 Tabtrail，然后点击图标打开侧边栏。
5. 点击侧边栏左上角 Logo，可在完整标签页中打开面板。

如果仓库 Releases 已提供 `tabtrail-版本号.zip`，也可以下载该文件、解压后直接选择解压目录。它与 GitHub 自动提供的 **Source code (zip)** 不同：后者包含整个项目，需要再选择其中的 `extension` 文件夹。

**更新已有安装**：更新原安装目录中的扩展文件，在扩展管理页点击“重新加载”，再重新打开面板。涉及视频检测脚本时，也请刷新已打开的测试网页。不要靠卸载重装更新，否则会删除该扩展的本地数据。

## 第一次使用

打开一些普通网页，再进入扩展工作区。未配置规则或 AI 时，页面通常会出现在“待整理”中。

- **先用本地规则**：点击“使用分类规则”，添加关键词并选择工作区。关键词匹配页面标题和域名，不产生 AI 费用。
- **使用 AI 分类**：点击“配置 AI，开始整理”，选择供应商、填写 Key 和模型名称。可以先测试连接，再保存。测试连接本身也可能产生少量费用。
- **调整结果**：在页面详情里手动修改归属；在“更多 → 工作区管理”中新建、重命名或删除工作区。删除工作区会迁移页面，不会关闭浏览器标签。
- **重新判断分类**：使用“更多 → 重新分组”，确认当前范围后执行。它也可能调整手动分组；搜索可以缩小此次处理范围。

支持的适配器包括 DeepSeek、OpenAI、Anthropic Claude、Google Gemini、通义千问（百炼北京）和 Kimi（中国站）。模型名称可编辑；是否能调用取决于你的账户、模型和网络。见 [AI 配置说明](docs/AI-PROVIDERS.md)。

## 自动整理会消耗 token 吗？

本地规则匹配不会。配置 Key 后，需要 AI 判断的页面会发送到所选供应商并按其规则计费。

未变化的已分类页面通常复用结果；有新页面或标题变化提供新信息时，也可能重新检查积压的“待整理”页面。一批最多分类 200 页，大量页面会分批处理。**一次新增标签不一定只发送这一页的信息**，还可能附带分类上下文。

日常自动整理保留手动归属。关闭标签只会改变清单，本身不要求重做已缓存分类；如果仍有未完成的候选页面，同步后仍可能继续处理。失败后的五分钟内不自动重试，可用“更多 → 同步标签”主动重试。

## 数据保存在什么地方？

**记录默认开启，保存在当前浏览器的扩展本地存储中。** 关闭面板不会暂停后台本地记录；自动 AI 分类则需要工作区打开且可见。没有开发者中转服务器或跨设备云同步。

| 数据 | 当前处理方式 |
| --- | --- |
| 页面清单 | 保存标题、完整网址、分组等；最多最近 30 个本地日历日、5,000 条每日页面记录 |
| 浏览片段 | 保存前台页面的时间估算和切换顺序；最多 30 天、12,000 段，另有约 4 MB 的估算预算 |
| AI 分类输入 | 标题、域名、随机记录 ID、工作区名称与参考页面、已确认规则、已应用偏好；不单独发送完整 URL 字段、正文或浏览时长 |
| API Key | 按供应商保存在本机，重启后保留；不包含在规则备份中，不是系统钥匙串加密存储 |

数量或预算上限可能让记录提前移除，并不保证保留完整 30 天。标题、工作区名和你填写的规则或偏好本身可能含私人信息，即使没有单独发送完整 URL 字段也应留意。

在“更多 → AI 配置与隐私”中，可以暂停记录、排除网站、清除 Key，或清空浏览记录并暂停。已发出的 AI 请求无法撤回。完整说明与权限用途见 [隐私说明](PRIVACY.md)。

## 使用边界与常见问题

- **时间为什么是估算？** 普通页面默认无操作 5 分钟后暂停，可选 1／5／10／15 分钟；前台视频播放可继续估算，锁屏或离开 Chrome 时暂停。静读、自动播放和特殊播放器可能影响准确性。
- **能找回安装前的历史吗？** 不能。只记录安装后、记录开启期间采集到的页面，不读取 Chrome 的完整浏览历史。
- **恢复的是整个工作现场吗？** 恢复的是仍保留的页面网址和分组，不包含滚动位置、表单、登录状态或窗口布局。
- **为什么删除规则后，旧分类还在？** 删除规则不会撤销已有分类。需要重新判断时使用“重新分组”。
- **能备份所有数据吗？** 当前导入／导出只支持分类规则和可选的已保存 AI 偏好，不是浏览记录或完整配置备份。
- **本机预览为什么看不到我的标签？** 网页预览只使用示例数据。需要通过扩展管理页加载后，才能读取真实标签。

## 开发与反馈

扩展运行时没有第三方 npm 依赖。开发检查需要 Node.js 20+，本地预览和打包另需 Python 3。在项目根目录运行：

```sh
npm test
npm run check
```

本地预览、浏览器测试和打包方式见 [贡献指南](CONTRIBUTING.md)。普通问题和建议可在本仓库 Issues 提交；请使用虚构页面复现，不要上传 Key 或私人浏览记录。

截至 2026-09-20，68 项 Node 测试、静态检查和三套浏览器网页回归通过。其中 Chrome API 与 AI 请求包含模拟边界；真实扩展休眠恢复、真实供应商调用、特殊播放器及存储压力仍待验收。详见 [验证记录](docs/CODE-AUDIT-20260920.md)。
